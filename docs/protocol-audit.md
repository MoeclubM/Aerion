# 协议实现检查

本轮检查覆盖协议入口、认证、TCP 转发、UDP 分片、连接生命周期及配置拒绝行为。自测互通可以发现内部回归，但不能替代与各协议官方实现的互通验证；当前 CI 对 Sudoku 另有固定版本的官方 Go 对端测试。

## 检查结果

| 协议或公共层 | 本轮结果 | 仍有的边界 |
| --- | --- | --- |
| 公共转发与记账 | 转发从 `core.rs` 拆到 `relay.rs`，保留原有公开接口；空闲或阻塞中的转发响应撤销，关闭两侧写半部；上下行共用原子配额计数 | 首个方向结束后关闭整个隧道，遵守现有 first-finisher 行为 |
| AnyTLS | 心跳保留正在读取的帧；撤销关闭控制连接；FIN 清理待开流；客户端完成流后立即回收注册项，取消开流或转发任务时关闭不可安全复用的会话；流 ID 耗尽不会回绕；监听停止后释放空闲会话池 | 多路复用流读写仍经过有界队列；不能假定各流完全独立 |
| Hysteria2 | 数据报任务使用弱引用；最后一个客户端释放时关闭 QUIC；分片数量和总长度有上限，并定期回收 | Gecko / Brutal 及 masquerade 未实现 |
| TUIC v5 | 分片锁不跨 DNS、限速或网络发送持有；与 HY2 共用有界重组器 | 官方对端互通仍需独立验证 |
| VMess | 加密器和认证长度密钥按连接复用；读取使用栈上小缓冲和原地解密；TCP 与各服务端 UDP 转发响应空闲撤销；客户端 TCP 实际计账；请求与响应、两种 AEAD、填充及认证长度有回归覆盖 | 官方对端互通与长连接边界仍需独立验证 |
| Shadowsocks | 畸形或未授权 UDP 包不再终止监听；接收缓冲复用；回包统一 IPv4 映射地址；TCP 与 UDP 监听任务生命周期绑定；客户端 TCP 实际计账并使用公共转发 | TCP 多用户记账缺少依赖库暴露的认证用户身份，当前显式拒绝；SIP003 插件未实现 |
| Naive | TCP 与 H3 监听互相监督，子监听失败向调用方返回，父任务结束时取消子监听；三种 HTTP TCP 转发均响应空闲撤销并关闭两侧写半部；客户端 TCP / UDP 实际计账；UDP 对端更新不会打断分帧读取；连接驱动与有上限的 UDP 子任务随隧道释放 | 协议测试覆盖不等于 Chromium/naiveproxy 官方互通证明 |
| VLESS / Vision / REALITY | 复用修正后的公共 TCP 转发；Vision 专用转发响应空闲撤销；XUDP 对端更新不会打断分帧读取；现有传输、UUID 与 Vision 测试作为回归检查 | XHTTP 仅 `stream-one`；Reverse 与 ML-KEM 解密未实现 |
| Trojan | 复用修正后的公共 TCP 转发；现有 TCP / UDP / 传输测试作为回归检查 | HTTPS fallback 对象仍显式拒绝 |
| Mieru | 检查现有 stream / packet underlay、会话关闭及 UDP over stream 路径，保留现有回归测试 | 非零 low-entropy 等尚未支持的整形配置仍显式拒绝 |
| HTTP / SOCKS / 直连 | SOCKS 只选择客户端实际提供的认证方式，并验证保留字节；现有 CONNECT 和路由测试作为回归检查 | HTTP CONNECT 不提供原生 UDP；直连维持 TCP 半关闭语义 |
| TLS / ECH / 配置兼容 | 保留不支持字段的显式报错及现有解析测试 | 客户端 ECH 未实现；生成的 uTLS ClientHello 不代表 rustls 线上握手完全匹配官方指纹 |

## 架构与性能

- `core.rs` 负责用户、会话、计数和限制；`relay.rs` 负责字节流转发与关闭。现有 `core::relay_*` 路径通过重导出保持兼容。
- `udp_fragments.rs` 只负责分片数据的长度限制、重复检测和重组。HY2 / TUIC 各自保留地址、会话和协议元数据规则。每连接最多保留 64 个待重组包，每包最多 65,535 字节；缓存仍有超时。
- 重组器维护剩余分片计数，避免每次到包扫描全部分片；完成时按总长度预分配一次输出缓冲。
- VMess 的 KDF、ChaCha 密钥派生及 AES 密钥扩展从每块执行改成每连接执行；入站解密复用接收缓冲，长度与填充缓冲不再逐块堆分配。
- UDP 接收队列满时丢弃该数据报，避免一个慢会话阻塞整条 QUIC 连接；TCP 字节流仍使用背压，不采用丢包方式。

## 验证范围

默认 `ci.yml` 覆盖格式检查、编译检查、单元与网络测试、Windows / Linux / macOS、iOS device / simulator、Android arm64，以及 Sudoku 官方互通。Linux 另运行 VMess 认证长度加密的 release 微基准；该结果衡量密钥缓存开销，不是整条代理链路吞吐率。

所有未实现能力继续显式报错。未提供上游互通或生产流量验证的分支，不据此宣称完全符合官方协议。
